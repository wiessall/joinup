* Purpose & scope
This register states *what* the redesigned STI Portal / ATIO KB must do and which qualities it
must have. It deliberately excludes:
- business rationale and funding logic → CAPEX proposal,
- architecture and technology choices (joinup, CQRS dual-DB, triplestore, Solr, Milvus, the JSON import schema) → Design Doc v4.2 and Architecture Decision Records (ADRs).
Each requirement referencing a design choice points to the ADR that owns it, so requirements stay stable while the "how" evolves under agile.

* Glossary
- AFSI :: Agrifood System Innovation — the *content* / knowledge unit. This encompasses both original records and ATIO innovation records or other representations in the platform.
- AFSA :: Agrifood System Actor — a *person or organisation* (policymaker, innovator, farmer rep, researcher, funder).
- Claim :: an AAA-style statement a collection makes about an AFSI; stored alongside slim core
  fields rather than forced into a fixed schema.
- Collection :: a data source's own body of records, retaining its own vocabulary/taxonomy.
- Connected :: a notebook-style entry of a AFSA in another AFSA's profile
- Relevant (to an actor) :: Topic or interest matches AFSA's interests
- AAA :: "Anyone can say Anything about Anything" — the semantic-web principle underlying the
  claims model.
- FAIR :: Findable, Accessible, Interoperable, Reusable.
- SKOS :: Simple Knowledge Organization System (vocabulary/taxonomy exchange).
- RAG :: Retrieval-Augmented Generation — an application pattern over a vector-search endpoint,
  not itself a query interface.
- ADR :: Architecture Decision Record.

* Constraints & assumptions
These are /givens/, not choices. They are not requirements and must not be confused with them.

** PROPOSED Drupal engine is retained
:PROPERTIES:
:ID: CON-01
:SOURCE: Henry Burgsteden; Design Doc §V.B
:END:
The Drupal engine remains the content-handling and orchestration layer (team skills, consultant pool, de-facto public-sector standard).

** PROPOSED FAO GCP hosting
:PROPERTIES:
:ID: CON-02
:SOURCE: Design Doc §V.A
:END:
The system is hosted on FAO Google Cloud Platform, with edge → review → production CD.

** PROPOSED No regression of ATIO curation
:PROPERTIES:
:ID: CON-03
:SOURCE: Valeria
:END:
The redesign shall not remove any curation capability the ATIO team currently relies on, and existing ATIO curation workflows (analysis, synthesis, standardisation) shall remain operational. (This absorbs the old "existing workflows keep working" acceptance line, which was a non-regression check rather than a forward requirement.)

** PROPOSED Interoperability with FAO infrastructure
:PROPERTIES:
:ID: CON-04
:SOURCE: uploaded note
:END:
The system must interoperate with existing FAO infrastructure and vocabularies (AGROVOC, FAOSTAT, …).

** PROPOSED Deliver the promised scope
:PROPERTIES:
:ID: CON-05
:SOURCE: CAPEX proposal; Design doc
:END:
The redesign must deliver what the CAPEX proposal and ATIO Design Doc outline.

* Functional requirements
** Data agglomeration                                           :AGG:
*** PROTOTYPE [#A] Import preserves original key–value pairs
:PROPERTIES:
:ID: FR-AGG-01
:MODAL: shall
:SOURCE: uploaded note ("maintaining existing key-value pairs"); AAA/claims model
:DESIGN: ADR-TBD (claims / semantic data model)
:END:
The system shall import a source record supplied in a supported format, preserving the source's original field names and values without mapping them onto a fixed schema.
- Acceptance: two structurally different sources load through the same path, and every original key–value pair is retrievable afterwards.
- Supported formats are structured data (JSON, XLSX, CSV, XML, SQL).

** Curation                                                        :CUR:
*** PROPOSED [#A] Non-developer curator can author records via GUI
:PROPERTIES:
:ID: FR-CUR-01
:MODAL: shall
:SOURCE: CAPEX; problem statement
:DESIGN: ADR-007 (Drupal + Workbench)
:END:
A content curator without software-development skills shall be able to create, edit, and submit an innovation record for review through a graphical interface, without writing code or running CLI commands.
- Acceptance: a non-developer completes record creation → submission in a usability test with no CLI use.

*** PROTOTYPE [#A] Maintainer can curate SKOS relationships
:PROPERTIES:
:ID: FR-CUR-02
:MODAL: shall
:SOURCE: Tristan Wiessalla
:DESIGN: ADR-008
:END:
A data curator can match semantic dimensions across collections using SKOS (e.g. 'Technological Readiness' of collection A similar to 'Readiness' of collection B)

*** PROTOTYPE [#B] Challenge organization
:PROPERTIES:
:ID: FR-NET-06
:MODAL: should
:SOURCE: Henry Burgsteden; Nikola Trendov
:END:
An actor (AFSA) with an organiser role should be able to create an innovation challenge on the platform and collect idea submissions from other actors.
- Out of scope: assessment, scoring, or ranking of submissions (collection only, no adjudication).
- Acceptance: an organiser creates a challenge; a second actor submits an idea to it; the submission is stored and visible to the organiser; no scoring/ranking UI is present.

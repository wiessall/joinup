#+TITLE: ATIO facets — import AFTER the index fields exist

These 10 facet config entities are *deliberately not* in =config/install=.

A facet whose =field_identifier= is not a field on =search_api.index.published=
throws =InvalidQueryTypeException= from =SearchApiBaseFacetSource=. The facet
source enumerates *every* facet assigned to it, whether or not the facet is
placed in a collection's listing settings, so one such facet makes every page
that renders that listing fatal — not just the facet.

There is no way to express "depends on an index field" in config dependencies,
so this ordering cannot be enforced by =cim=. It is enforced by keeping these
files out of the auto-installed directory.

* Order

1. Add the 10 index fields (=atio_indexing_steps.sh=, section 1).
2. Verify every one reports OK (=unbreak_and_verify.sh=, section B).
3. Index the records.
4. Only then:

#+begin_src sh
ddev drush cim --partial --source=web/modules/custom/atio/config/facets
ddev drush cr
#+end_src

5. Place them per collection (=atio_indexing_steps.sh=, section 4).

* Rolling back

Deleting the facet entities is always safe and instantly restores rendering:

#+begin_src sh
ddev drush ev '$s = \Drupal::entityTypeManager()->getStorage("facets_facet"); foreach (["atio_readiness_level","atio_adoption_level","atio_innovation_stage","atio_form_of_innovation","atio_innovation_type","atio_use_cases","atio_thematic_area","atio_challenges_addressed","atio_sdg_targets","atio_country_origin"] as $id) { if ($f = $s->load($id)) { $f->delete(); } }'
#+end_src

#+Title: README

This module takes care of minting the URIs and providing functionality to write to the triplestore. It extends ~rdf_sync~ in the following ways:
  - skos mapping functionality. This is a basic design decision: Curators (human or machine) should be able to create semantic mappings between the various collection taxonomies. This is needed for a semantically meaninful derivation of a standardized derivation across all ~source_record~. This derivation is the ~atio_innovation~.
  -

** MappingTermSource
Fetches the ATIO and STI taxonomies to populate the dropdown menu in ~skos_curation.html.~ It knows about which taxonomies to fetch by selecting those with child terms. It also gets the relevant triplestore uris for each of them. Controlled by ~MappingTermsController~.
** OntologyDocumentBuilder
The output layer of ~skos_curation.html~. Handled by ~OntologyController~. The controller ultimately returns the response (by default the ttl mappings).
** MappingReader
This gets the bundle rdf third-party config alongside the bundles fields' rdf third-party configs, to be used by: OntologyDocumentBuilder, MappingTermSource
** StiRdfUriCommands
This controlls all remaining services:
+ ~MappingImporter~
+ ~UriReminter~
+ ~GraphSynchronizer~
My suspicion is that these are useful tools for development on a live database on-the-fly, but might not be needed in final production
